# Ten questions the vocabulary exists to answer

Generated by `scripts/21_use_cases.py`, by running each query against the shipped graph: `derived/abox/censo-waterbase.ttl` plus the vocabulary, both regulation packages and the alignment (508,050 triples).

**The counts are of the materialised graph, not of the population.** The knowledge graph is a 40,000-row reservoir sample with a fixed seed, because a pure-Python triple store cannot hold 4.19 million station-years; the manuscript's headline figures are computed over every assessable row by `scripts/22_waterbase_external.py` and are larger. What these queries demonstrate is that the question is *askable* and what the answer looks like, not the size of the finding.

The competency questions in `queries/` are tied to axioms — each shows that a construct works. This document answers a different question, the one somebody deciding whether to adopt this actually has: **what can I ask on Monday that I cannot ask now?** So every scenario names who asks it, and every scenario says what a two-valued schema returns instead. That contrast is the contribution; the class hierarchy is only how it is delivered.

---

## 1. How many of the verdicts in this report are not actually supportable, and for which reason each?

**Asked by:** A competent authority preparing a status report

```sparql
SELECT ?outcome (COUNT(?o) AS ?n) WHERE {
          ?o a ?outcome .
          VALUES ?outcome { censo:Compliant censo:Exceedance
                            censo:MethodInsufficient censo:PreconditionUnmet
                            censo:PossibleExceedance censo:BoundNotEstablished }
        } GROUP BY ?outcome ORDER BY DESC(?n)
```

| outcome | n |
|---|---|
| Compliant | 21719 |
| PreconditionUnmet | 7577 |
| MethodInsufficient | 6885 |
| BoundNotEstablished | 2619 |
| Exceedance | 857 |
| PossibleExceedance | 343 |

*17.7s*

**What a two-valued schema returns instead.** Returns two columns, compliant and exceeding, and every undecidable row lands in one of them. Which one depends on the substitution constant the pipeline happened to use, and nothing in the output records that a choice was made.

**Reading it.** Every row that is not Compliant or Exceedance is a verdict the record cannot support, and the class says why. That column does not exist in a two-valued schema, so those rows are silently counted as one of the other two.

## 2. For which substances is my quantification limit above the legal standard, so that a clean 'not detected' still decides nothing?

**Asked by:** A laboratory manager choosing which methods to upgrade

```sparql
SELECT ?substance (COUNT(?o) AS ?n) WHERE {
          ?o a censo:MethodInsufficient ;
             censo:hasAnalyte ?a .
          ?a rdfs:label ?substance .
        } GROUP BY ?substance ORDER BY DESC(?n) LIMIT 12
```

| substance | n |
|---|---|
| Chlorpyrifos (Chlorpyrifos-ethyl) | 1299 |
| Hexachlorobutadiene | 910 |
| Fluoranthene | 778 |
| Dichlorvos | 655 |
| Cypermethrin ( 22 ) | 360 |
| Dicofol | 232 |
| Diuron | 230 |
| Imidacloprid | 225 |
| Pentachlorobenzene | 202 |
| Cybutryne | 197 |
| Silver | 158 |
| Permethrin | 128 |

*0.9s*

**What a two-valued schema returns instead.** Reports these as compliant. The laboratory looks efficient and the substance looks clean, and the two facts have the same cause.

**Reading it.** Ranked by how much of the record the defect costs. This is the list a method-development budget should be spent against, and it cannot be produced from a table of concentrations because the rows it names look like compliance.

## 3. Show me only the exceedances I could defend: a quantified value above the standard, from a method that meets the legal performance criterion, with an interval that does not straddle the limit.

**Asked by:** An enforcement lawyer

```sparql
SELECT (COUNT(?o) AS ?affirmable) WHERE {
          ?o a censo:Exceedance ; a censo:QuantifiedObservation .
        }
```

| affirmable |
|---|
| 857 |

*0.1s*

**What a two-valued schema returns instead.** Cannot express the question. Its exceedance count depends on the substitution rule, and it has no way to mark which exceedances rest on a measurement and which on a convention.

**Reading it.** The affirmable count. A pipeline substituting half the limit reports many times this number over the same rows, and the difference is not measurement but convention.

## 4. Which rows tell me the result was below the limit and give me a positive number for it anyway?

**Asked by:** A data steward receiving a national submission

```sparql
SELECT (COUNT(?o) AS ?substituted) WHERE {
          ?o a censo:CensoredObservation ;
             censo:reportedValue ?v .
          FILTER (?v > 0)
        }
```

| substituted |
|---|
| 30888 |

*5.7s*

**What a two-valued schema returns instead.** Sees only the number. The flag and the value sit in different columns and nothing relates them, so the contradiction is invisible unless somebody writes a bespoke script to look for it.

**Reading it.** The substitution has already happened before anyone downloads the data. censo:CensoredObservationShape catches this as a published constraint rather than a one-off script, which is what makes it checkable by the party receiving the submission.

## 5. For this assessment, which conditions of the standard are satisfied, and which cannot be evaluated from what was reported?

**Asked by:** An assessor asked whether a limit even applies here

```sparql
SELECT ?condition (COUNT(?o) AS ?n) WHERE {
          ?o censo:conditionSatisfied ?condition .
        } GROUP BY ?condition
```

| condition | n |
|---|---|
| eu-2008-105-2026-cond-matrix | 35318 |

*1.4s*

**What a two-valued schema returns instead.** Has a threshold column with a number in it. There is nowhere to record that the standard is defined on a quantity nobody measured, so an inapplicable limit is applied and the verdict looks like any other.

**Reading it.** Applicability is asserted, not assumed: the graph says which condition was met. Where a condition names a covariate the record does not report, the observation is censo:PreconditionUnmet instead, and the count above for that class is the size of that stratum.

## 6. Take one assessment that cannot be decided. What is the reason, in the graph, without reading the pipeline's source?

**Asked by:** Anyone reading a single row and asking why it is undecidable

```sparql
SELECT ?substance ?reason ?upper ?limit WHERE {
          ?o a censo:MethodInsufficient ;
             a censo:CensoredObservation ;
             censo:hasAnalyte ?a ;
             censo:resultUpperBound ?upper ;
             censo:assessableAgainst ?t .
          ?a rdfs:label ?substance .
          ?t censo:thresholdValue ?limit .
          BIND("the quantification limit exceeds the standard (Art. 3(3b))"
               AS ?reason)
        } LIMIT 5
```

| substance | reason | upper | limit |
|---|---|---|---|
| Permethrin | the quantification limit exceeds the standard (Art. 3(3b)) | 0.02 | 0.00027 |
| Imidacloprid | the quantification limit exceeds the standard (Art. 3(3b)) | 0.0099999998 | 0.0068 |
| Diuron | the quantification limit exceeds the standard (Art. 3(3b)) | 0.05 | 0.049 |
| Cybutryne | the quantification limit exceeds the standard (Art. 3(3b)) | 0.01 | 0.0025 |
| Trifluralin | the quantification limit exceeds the standard (Art. 3(3b)) | 0.05 | 0.03 |

*0.0s*

**What a two-valued schema returns instead.** Offers a verdict and no reason. To find out why, you read the code that produced it, if you have it.

**Reading it.** The reason travels with the row. The upper bound is what the non-detection established and the threshold is what it had to decide; the first being above the second is the whole finding, and it is legible from the graph alone.

## 7. The same measurement, under two regulations. Are they even talking about the same substance, and do they agree?

**Asked by:** A basin authority on a border, or anyone comparing regimes

```sparql
SELECT ?eu ?tr ?cas WHERE {
          { ?eu owl:sameAs ?tr } UNION { ?tr owl:sameAs ?eu }
          ?eu censo:casNumber ?cas .
          FILTER (STRSTARTS(STR(?eu), "https://w3id.org/censo/reg/analyte-eu-"))
          FILTER (STRSTARTS(STR(?tr), "https://w3id.org/censo/reg/analyte-tr-"))
        } ORDER BY ?cas LIMIT 8
```

| eu | tr | cas |
|---|---|---|
| analyte-eu-Imidacloprid | analyte-tr-Imidakloprid | 105827-78-9 |
| analyte-eu-Thiacloprid | analyte-tr-Tiakloprid | 111988-49-9 |
| analyte-eu-Nicosulfuron | analyte-tr-Nikosulfuron | 111991-09-4 |
| analyte-eu-Endosulfan | analyte-tr-Endosulfan | 115-29-7 |
| analyte-eu-Anthracene | analyte-tr-Antrasen | 120-12-7 |
| analyte-eu-Quinoxyfen | analyte-tr-Kinoksifen | 124495-18-7 |
| analyte-eu-Acetamiprid | analyte-tr-Asetamiprid | 135410-20-7 |
| analyte-eu-Imidacloprid | analyte-tr-Imidakloprid | 138261-41-3 |

*0.1s*

**What a two-valued schema returns instead.** Needs a name-matching script, and gets one verdict per run because the threshold is a column rather than a citable object.

**Reading it.** The substances are reconciled by owl:sameAs in ontology/censo-alignment.ttl, so the comparison is an entailment rather than a string join across two spellings. Both packages can be loaded at once because each threshold cites the regulation that defines it, and two verdicts about two jurisdictions' thresholds are not a contradiction -- the disjointness is per observation-threshold pair.

## 8. Which substances has this network never once been able to decide, at any station, in any year?

**Asked by:** A programme designer choosing what to monitor next

```sparql
SELECT ?substance (SUM(IF(?cls = censo:MethodInsufficient, 1, 0)) AS ?n)
        WHERE {
          VALUES ?cls {
            censo:MethodInsufficient censo:Exceedance censo:Compliant
          }
          ?o a ?cls ; censo:hasAnalyte ?a .
          ?a rdfs:label ?substance .
        }
        GROUP BY ?substance
        HAVING (SUM(IF(?cls != censo:MethodInsufficient, 1, 0)) = 0)
        ORDER BY DESC(?n) LIMIT 10
```

| substance | n |
|---|---|
| Esfenvalerate | 67 |
| Bifenthrin | 62 |
| Deltamethrin | 50 |

*9.9s*

**What a two-valued schema returns instead.** Reports them as compliant everywhere, so they look like the clean part of the programme and the budget goes elsewhere.

**Reading it.** Substances with method-insufficient assessments and no decided assessment of either kind: monitored, reported, and never once decided. A two-valued record cannot distinguish them from substances that were measured and found absent.

## 9. Can I check this submission against a published constraint rather than a script I wrote myself?

**Asked by:** A data steward validating an incoming national submission

```sparql
SELECT ?shape (COUNT(?o) AS ?targets) WHERE {
          VALUES (?shape ?cls) {
            ("CensoredObservationShape" censo:CensoredObservation)
            ("AnalyticalMethodShape"    censo:AnalyticalMethod)
            ("ThresholdShape"           censo:Threshold)
          }
          ?o a/rdfs:subClassOf* ?cls .
        } GROUP BY ?shape ORDER BY DESC(?targets)
```

| shape | targets |
|---|---|
| CensoredObservationShape | 31167 |
| AnalyticalMethodShape | 1159 |
| ThresholdShape | 537 |

*2.1s*

**What a two-valued schema returns instead.** Offers no constraint to check against. Each recipient writes their own script, and what one accepts another rejects.

**Reading it.** The shapes ship with the vocabulary at a resolvable IRI, so the party receiving a submission and the party sending it can run the same check and disagree about the data rather than about the rules.

## 10. If the threshold is swapped for another jurisdiction's, which assessments change and which are untouched?

**Asked by:** A ministry asked what adopting a different standard would change

```sparql
SELECT ?package (COUNT(?t) AS ?thresholds) WHERE {
          ?t censo:definedBy ?package .
        } GROUP BY ?package
```

| package | thresholds |
|---|---|
| eu-2008-105-2026 | 103 |
| tr-ysky-2016 | 434 |

*0.0s*

**What a two-valued schema returns instead.** Has one threshold per substance, so the question requires editing the column and losing the previous answer. Nothing records which standard produced which verdict.

**Reading it.** Every threshold cites the instrument that defines it, so both packages load at once and a verdict carries its provenance. Section 5.7 counts what changes; the vocabulary is what makes the count possible without running the pipeline twice against two edited copies of the data.

## What these have in common

None of the seven is answered by adding a column. Each needs the record to carry something a table of concentrations throws away: that a number is a bound rather than a measurement, that a threshold has conditions, that a verdict has a reason, or that two regulations name one substance. Where the information is gone, no estimator and no substitution rule recovers it — which is why the argument is about representation and not about statistics.
