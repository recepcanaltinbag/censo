Between the smallest and largest ABox the observation count grows 16-fold and closure time 39-fold, so the cost is super-linear in this range.

## Honest reading

RL closure is materialising: every entailment is written into the graph, so memory and time grow with the entailed set, not merely with the asserted one. This is the right configuration for a reproducible, JVM-free pipeline and it is what the reported figures describe. A production deployment over a full basin would use a triple store with native rule support rather than in-memory materialisation, and these numbers should not be read as a limit on the approach.
